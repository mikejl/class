ML security and ethics: when the model is the target

Every page so far assumed the data was honest. Attackers do not cooperate. A machine learning system has every vulnerability of ordinary software, plus new ones: its behavior comes from data, so whoever influences the data or the inputs can influence the decisions.

A field guide to attacks on ML

AttackWhat the attacker doesMain defenses
evasion (adversarial examples)Crafts inputs that are misclassified at prediction time, such as malware padded to look benign or a stop sign with stickers.Adversarial training, robust features the attacker cannot cheaply change, ensembles
poisoningSlips bad examples into the training data, for example through user-submitted samples or a scraped dataset.Data provenance, outlier filtering, limiting who can contribute labels
backdoorPoisons training so the model behaves normally except when a secret trigger appears.Trusted training pipelines, model scanning, verifying third-party models
model extractionQueries a model's API many times and trains a copy from the answers, stealing the work and making evasion easier.Rate limiting, query monitoring, returning labels instead of exact probabilities
membership inferenceDetermines whether a specific person's record was in the training data, a privacy leak.Regularization (page 07), differential privacy, less confident outputs
prompt injectionHides instructions in text an LLM reads, such as a web page or email, to hijack what it does.Treat model output as untrusted, least-privilege tool access, human approval for sensitive actions
supply chainTampers with libraries, pretrained models, or model files. Some model file formats, such as Python pickle files, can run code when loaded.Pin dependencies, verify hashes, prefer safe formats such as safetensors

Ethics: harm without an attacker

Some of the most serious ML failures involve no attacker at all. A model learns whatever patterns are in its data, including unfair ones.

bias

A model trained on past hiring decisions can learn past discrimination. Face recognition trained mostly on one group performs worse on others. Measure performance separately for each group, not just overall.

privacy

Models can memorize and leak training data, including personal information. Collect only what you need and control who can query the model.

transparency

People affected by automated decisions, such as being flagged for fraud, deserve an explanation and a way to appeal to a human.

accountability

"The model decided" is never an excuse. A person or organization owns every deployed model and its mistakes.

Frameworks to know: MITRE ATLAS catalogs real-world attacks on AI systems in the style of ATT&CK. The OWASP Top 10 for LLM Applications and the OWASP Machine Learning Security Top 10 list the most common weaknesses. The NIST AI Risk Management Framework guides organizations in governing AI risk. Links are on the further learning page.
  • ML adds attack surface at every pipeline stage: data, training, model files, the prediction API, and inputs.
  • Evasion attacks fool a trained model; poisoning corrupts it during training; extraction and membership inference steal from it.
  • Responsible ML also means checking for bias, protecting privacy, explaining decisions, and keeping humans accountable.
