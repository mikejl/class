Stream & Block Ciphers, One Gate at a Time

Every symmetric cipher scrambles data with a key. The difference between a stream cipher and a block cipher is really a difference in how much data gets combined with the key at once — and the XOR gate is where that combination actually happens.

The XOR Gate

XOR ("exclusive or") outputs 1 when its two inputs differ, and 0 when they match. That single rule is the engine behind most symmetric ciphers: it's cheap to compute, and — critically — applying the same key bits a second time undoes the first pass.

Two Ways to Encrypt a Message

Both approaches use a secret key to turn plaintext into ciphertext. They differ in whether they process the message continuously or in fixed-size chunks. Try both panels below.

Stream Cipher bit by bit

A keystream generator produces an endless run of pseudorandom bits from the key. Each bit of plaintext is combined with the matching keystream bit — usually with XOR — the instant it arrives.

Click any keystream bit to flip it — the output updates instantly, one position at a time.
  • Examples: RC4, ChaCha20, Salsa20
  • Good for: real-time data — voice, video, network links

Block Cipher fixed chunks

The message is split into fixed-size blocks. Each full block is transformed through several rounds of substitution and permutation, keyed by the secret. Short final blocks get padded.

  • Examples: AES, DES, Blowfish
  • Good for: files, storage, anything not streaming live
Where they meet: a block cipher run in CTR mode uses the block cipher only to generate a keystream from a counter — then XORs that keystream with the plaintext, exactly like a stream cipher. The XOR step above is the same operation either way.
